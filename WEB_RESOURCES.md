## Six new animation and cinema references — reviewed production path

The six user-supplied sources support a possible research path: motion
reference (Sakugabooru), shot composition (SHOT.CAFE), original 3D poses
(PoseMy.Art), historical outfit reference (Niwatoliver), custom anime
video-prompt drafting (YouMind), and optionally hosted image-to-video
experiments (Carat). They **do not constitute an automatic end-to-end
video pipeline**. Every site is separately assessed for each repository;
only explicit motion/cinema/pose/costume/video project signals can match,
and every reference retains `integrationEligible: false`.

- **Copyright:** Anime clips and film stills can inspire original work but
  are not licensed production frames. No copying, scraping, training or
  importing proprietary content by default.
- **Historical sources:** The costume site itself identifies 1,639 historic
  source images as public-domain/CC0 and its own dress line art as CC0;
  check individual provenance and distinguish user-submitted designs.
- **External computation:** A YouMind prompt listing is not free video
  inference; Carat is a third-party AI service with potentially paid
  usage, licence and private-input restrictions.
- **Specialist use:** A general-purpose game, speech, trading, coupon or
  software project does not automatically need any of these six sites.
  Site research is nonexecuting metadata guidance, not an instruction to
  run arbitrary web content or contact external accounts.

## Quantized image checkpoints are references, not plug-and-play dependencies

`AtomicChat/FLUX-3-Image-Klein-GGUF` is tagged `gguf` and
`stable-diffusion.cpp` on its Hugging Face model page; the page reports
`license: other`. It is a community quantization of Black Forest Labs'
`flux-3-image-klein`, which uses the **FLUX Kommunity License**. This
requires reviewing the actual upstream and conversion terms before
commercial use, distribution or embedding a model in an application.
A GGUF transformer on its own does **not** supply the text encoder, VAE
or a functioning Android/mobile inference service, and a file-size estimate
does not prove GPU RAM sufficiency.

This checkpoint is considered for project-specific image, sprite, texture,
visual or asset-generation needs, including hyphenated description/topic
labels. It is excluded from generic AI and speech project recommendations.
It remains `integrationEligible: false` even if relevant. The daily scan
records its provenance and explicit non-selection reasons for other projects.

## Hugging Face discovery and MiniCPM safety

The Hugging Face homepage is a **model/dataset/Spaces discovery directory**.
It can be reviewed for AI-agent and AI-media repositories, without assuming
that each hosted model is free, open-licensed, safe or actually served by an
Inference Provider. Each candidate's license, hardware, hosted costs and
privacy requirements must be reviewed individually.

`saidutta69/MiniCPM-V-4.7-1B-heretic` is an `image-text-to-text`
vision-language model derived from `openbmb/MiniCPM-V-4.7-1B`. Its
Hugging Face card labels it Apache-2.0 and approximately **1.55B total
parameters**, 1.01B for language and 0.55B for the vision encoder.
**Its "heretic" modification deliberately reduces refusals and supplies
no additional moderation/safety filter**. Never use it as an autonomous,
unmoderated public-facing agent. Independently verify rights, document
handling/privacy, on-device performance and any safeguards.

For llama.cpp vision inference the model card states that GGUF use needs
**both** the quantized main model and its approximately **1.11GB vision
projector** (`mmproj`). CPU/GPU memory, supported formats and device
compatibility require actual testing; 1B in the title is not the complete
multimodal parameter count. This is a review-only resource, **not an
automatic dependency or a known working Android integration**. The
selection engine prefers projects with explicit OCR, screenshot, image
understanding, captioning or multimodal objectives; generic speech projects
and asset-generation apps do not receive this VLM simply because they
work with AI or images.

## SoPilot: discover a marketing workflow without automating public accounts

[SoPilot](https://sopilot.net/) is a commercial social-marketing service,
particularly focused on X trend research, AI-written posts, content
calendars, short kinetic videos and SEO directory/backlink submissions.
It uses a Chrome extension, user accounts and credit/subscription plans.
It is **not** a code library, general free model endpoint, or default
dependency for Android games and retail discount aggregators.

Star List adds a narrowly scoped `marketing` project domain based on
clear **GitHub repository labels** (`social`, `marketing`, `seo`,
`campaign`, `outreach`), never on arbitrary README instructions or
the word `promo` alone. A matching project receives **advisory-only**
guidance; this never triggers social publishing or browser automation.
The explicit `platform-anti-spam-and-account-policy-review` and
`manual-publication-and-consent-required` gates require account-owner
consent and platform-policy review before any outreach, replies, follows
or directory submission. Mass engagement can be spam, and low-quality
backlinking can harm reputation and rankings.

## Humanizer: keep writing use cases separate from developer agents

[Humanizer 12B](https://huggingface.co/jialinyyzz/humanizer) is a
Gemma-4 12B fine-tune, declared Apache-2.0, for rewriting an existing
draft in **English or Chinese**. It is a **completion model**, not a
general chat assistant or a vetted multilingual translator. As of its
published model card it has **no default Hugging Face hosted inference
provider**. GGUF and safetensors weights are available for compatible
local runtimes, but the approximately **7.6 GB Q4_K_M** GGUF checkpoint
alone makes direct Android deployment unproven. Smaller quantizations
can reduce fidelity.

The author reports that a strict judge found factual issues in **44 of
420 English rewrites**; formatting can also change. Treat marketing copy,
blog posts, newsletters, editorial drafts and email rewriting as
**human-reviewed** references only. The model is matched by explicit
writing/rewriting/copywriting labels, **not** by generic AI, code,
video editing or text processing. The source advertises an `AGENTS.md`
with install commands, but Star List treats it as **untrusted
third-party documentation** and does not execute it or automatically
download checkpoint files.

Matched project records and public issue references expose the
`factual-and-format-preservation-review`,
`source-and-target-language-review` and
`human-editor-approval-before-publication` gates in addition to the
usual model licence/runtime review. Names, figures, dates, quotations,
links and formatting must be checked against the original; neither
language preservation nor a particular AI-detector outcome is
guaranteed. Any academic or professional disclosure rules still apply.

## Explicit review gates in daily recommendations

Every qualified web reference carries `reviewGates` in the full
portfolio artifact and its matched `source_assessment` decision. The
daily public review issue also prints the relevant gates next to the
source, rather than concealing restrictions behind the generic phrase
"inspect reuse rights". Examples:

- MiniCPM-V Heretic: `reduced-refusal-public-safety-review` and
  `model-license-and-attribution-review`; never mistake an abliterated
  vision-language model for a moderated public endpoint
- AtomicChat FLUX.3: `unverified-hub-license-tag` plus model-runtime
  and commercial-licensing review
- Hosted generators: `hosted-terms-privacy-and-cost-review`
- Hugging Face Hub: `per-item-license-and-provider-review`

All websites and models remain `integrationEligible: false`; a
visible review gate is not proof of compatibility, working GPU access,
permission to redistribute weights, or successful target delivery.

## Complete per-project catalog decisions

The daily portfolio scan now evaluates **every catalogued GitHub repository and website**
for each active, accessible project and writes a per-entry decision to
`source_assessment.repositories` or `source_assessment.websites` in the
`portfolio-daily.json` Actions artifact. Each entry has `decision`,
`reason` and `integrationEligible`. The report enforces exact coverage of
the current curated catalogs before any model-worker dispatch and records the
total number of assessments in its summary. A rejected or review-only resource
is still assessed, not silently omitted. Archived target projects are explicitly
skipped; inaccessible/private targets require their own authorized credentials.

This is a **local, metadata-based relevance scan**, not thousands of fresh
network fetches, model inference requests or installations. A matching website
or hosted model is always reference-only and may require licensed weights,
hardware, payments or source review before practical use. The brief GitHub
issue displays top matches; the workflow's full JSON artifact preserves all
catalog entries, including nonmatching ones. Re-scans pick up the next catalog
version automatically.

## How specialist game platforms are selected

The daily portfolio scan inspects **all 33 curated web entries**, without a top-N cutoff. Game projects receive **Rosebud AI, Ludo.ai and modl.ai as review-only baseline options** even when their descriptions are sparse; they are not installed or invoked automatically. Convai, Inworld AI, Sloyd and Charisma require specific project metadata signals (such as NPC dialogue, voice, narrative or 3D assets). The scanner still excludes services unrelated to the project. Every hosted resource remains `integrationEligible: false`; hosted logins, credits, build uploads and licences require separate review.

The opt-in `--websites` flag adds `websiteRecommendations` separately from
`recommendations` in JSON output. Its site scores are **relevance cues**, not
GitHub quality/security scores. All website results carry
`integrationEligible: false`. The normal GitHub repository ranking, strict
repository filters, stacks, Stars sync and Production-OS integration handoffs
remain unchanged.

`--top-websites` controls the number of references (default 5). The normal
repository `--platform`, `--language`, `--self-hosted`, license and similar
hard filters **do not certify web inspiration pages**. A site may be useful
for visual research without matching the project's runtime.

## PINOC MCP — optional 3D animation tool for agents

The user's [PINOC app MCP link](https://viggle.ai/pinoc/app/mcp)
corresponds to the provider's
[PINOC MCP documentation](https://viggle.ai/pinoc/mcp). Its published
remote Model Context Protocol endpoint is:

```text
https://pinoc.mcp.viggle.ai/mcp
```

The website recommender includes the endpoint as **reference metadata**
(`mcpEndpoint`) but does not connect to it, write an MCP config, request
authorization or spend credits automatically. Before an agent can use PINOC,
a person must connect a compatible MCP client and complete the provider's
browser sign-in.

**Free operations:** browse or retrieve preset motion clips, inspect your
assets and check your credit balance. **Credit-consuming operations:**
generate a new motion from text or video (the provider documents
1 credit/second), or generate a 3D character (6–10 credits depending on
refinement). Start with the **read-only** scope. The generation scope must
be enabled explicitly by the user, only after reviewing the per-task cost.
Do not silently enable generation, upload photos or videos, or authorize
credits as part of a portfolio scan.

Animation clips can be exported as GLB/FBX (and USDZ where supported);
splat characters require the provider's compatible rendering integration
and are **not** standard mesh assets. For Blender, Unity, Unreal, Godot or
Roblox projects, validate the specific model/rig/format support in the actual
target engine before promising compatibility. Upstream terms and rights for
generated or preset assets require an independent check.

```bash
# Review relevant tools and the official endpoint; no network writes:
python scripts/recommend.py "3d character rigging mocap blender" --websites --json
```

The daily portfolio scanner suggests PINOC only when game, graphics or
media metadata supplies concrete 3D/motion/rigging evidence or an explicit
3D engine identifier such as Roblox, Unity or Unreal. This is an **advisory
research hint**; matching the engine name alone does not prove that a motion
clip can be retargeted to its rig or imported without conversions. It retains
Game Art Style as the main art-direction reference in game projects.
Neither site is an autonomous Production-OS integration candidate.

## Operating policy

- A link is not an open-source license. Verify individual component/shader
  licenses, source availability, third-party images, fonts and trademarks
  before any commercial reuse.
- Paid content remains paid; a free preview is not permission to scrape,
  bypass access controls or redistribute premium prompts/templates.
- No copying other websites verbatim without rights. Use galleries for design
  direction, then create original implementation and assets.
- Future website additions should use canonical HTTPS URLs, stable unique IDs,
  descriptive tags, access expectations and an explicit `reuse` policy.
  Validate against [`schemas/websites.schema.json`](schemas/websites.schema.json).
- During daily portfolio discovery, the scanner considers **all** websites
  and retains every genuinely relevant reference per repository, based on owned repository
  metadata and concrete keyword overlap. Game projects also receive
  **Game Art Style** as a prioritized art-direction reference when their
  GitHub description contains no design terms; unrelated domains are excluded
  and generic prose words (such as `and` or `for`) never qualify a match.
  When explicit 3D motion/rigging cues exist, PINOC MCP is prioritized
  immediately after Game Art Style; the Jupiter art-direction reference is
  also retained when game development applies. No MCP request,
  authorization or credit spend occurs during scanning.
  These suggestions are kept in the
  complete `website_references` workflow JSON artifact, separate from GitHub integration
  `suggestions`; the reference list is never entered into the dispatch queue.
- The existing `scripts/validate_websites.py` semantic validator checks
  HTTPS URLs, credential-free identity, aliases, duplicates and MCP endpoint
  host/path restrictions across records.
  No live crawling is performed during CI.
- Website entries are not auto-dispatched into target repositories. After
  selecting a compatible implementation, ordinary target CI, security review
  and the project's approval gates continue to apply.
